# v4.0 Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `hasyirin/laravel-kpi` as v4.0.0: one schema, one write path whose invalid states are database errors, and a calculator on integer seconds.

**Architecture:** Every write runs inside `ResourceLock`, which locks the resource row and retries. The movement model holds the one write path. Range lookups are plain reads, and a unique index on `(movable_type, movable_id, level_key, position)` rejects writes from stale reads. The calculator works in integer seconds, in `kpi.timezone`, and gets excluded days from `HolidayCalendar`.

**Tech Stack:** PHP 8.4, Laravel 13, Testbench 11, Pest, Larastan level 5, Pint. Databases: SQLite, PostgreSQL 17, MySQL 8.4, MariaDB.

**Spec:** `.docs/superpowers/specs/2026-10-30-v4-redesign-design.md`. Read it with this plan. Section references below (§) point to it.

## Review Focus

Each line has a test in the task that owns the code.

1. A resource registered in the morph map, with a custom primary key name: the lock must find the row through the alias (Task 5).
2. A soft-deleted resource: writes still work, because the lock ignores global scopes (Task 5).
3. A DST day where the schedule window has zero length: the calculator must not divide by zero (Task 3).
4. A table prefix on the connection: the `CHECK` statements must target the prefixed table (Task 4, database jobs only).
5. A movement open for more than two years: exact seconds, and `period` fits its column (Task 3).

- [ ] **Step 3: Implement `ResourceLock`**

`forResource` uses the instance's connection, table, key name and key. `forMovement` resolves the class with `Relation::getMorphedModel($type) ?? $type`, makes `new $class` without loading a row, and uses the class's connection name, or the movement's when the class sets none. This is the same rule as `MorphTo::createModelByType`. The lock is `$connection->table($table)->where($keyName, $id)->lockForUpdate()->value($keyName)`, so no global scope applies. A null result throws `LogicException`.

`run` determines this algorithm:

```php
$owned = $lock->transactionLevel() === 0 && $movementConnection->transactionLevel() === 0;
$maxAttempts = $owned ? 3 : 1;

for ($attempt = 1; ; $attempt++) {
    try {
        return $lock->transaction(function () use ($lock, $movementConnection, $callback) {
            $this->lockRow();

            return $lock === $movementConnection ? $callback() : $movementConnection->transaction($callback);
        }, $maxAttempts);
    } catch (UniqueConstraintViolationException $e) {
        if ($attempt >= $maxAttempts) {
            throw $e;
        }
    }
}
```
